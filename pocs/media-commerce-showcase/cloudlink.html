02 / FIELD SERVICE / CLOUDLINK

工程案子從發出需求，
到報價都能追蹤。

為資訊弱電、網路 AP、CCTV 與門禁等服務建立清楚的需求路徑。以「客戶發案 → 審核 → 工程師報價 → 客戶選擇」減少資訊散落與狀態不明。

弱電／資訊工程台南與南部服務驗證候選尚未正式上線
看四階段流程看驗收證據
服務能力尚未核定。這不是立即可用的發案平台，也沒有經核驗的公開師傅清單或付款保障。

DEMO FLOW

從一筆需求，留下完整的四步紀錄

  1. 01｜客戶描述問題選擇網路、CCTV 或門禁類別，輸入場景與需求。試驗中使用虛構資料。
  2. 02｜審核員檢視確認案件類別與基本欄位；目前僅示範流程，不代表正式服務保證。
  3. 03｜工程師提出報價記錄報價及方案；真實工程資格、成本估算與服務地區仍需驗證。
  4. 04｜客戶選擇與留存保存所選報價及狀態；付款與正式履約驗收功能均未啟用。

適用對象

中小型工程公司、弱電承包商，以及需要留下報修、報價與進度紀錄的客戶。

現有技術範圍

已記錄 FastAPI／SQLite 隔離工作流與原版 React 表單接線；正式登入、多租戶、通知、保固與金流仍未通過。

後續必要條件

實際工程商資格、合約和客服責任，以及真實 Staging 瀏覽器 E2E、權限隔離、安全審查和 Owner Gate。

PROOF / STATUS

目前已測的是流程，不是正式媒合服務

有來源支持的成果

  • 既有隔離 POC 的 FastAPI／SQLite 測試記錄：18/18 本機 pytest PASS。
  • 測試環境 127.0.0.1 的 socket/HTTP 合成發案→報價→選擇流程有通過紀錄。
  • 原版 React 發案處理器與隔離 API 的程式接線已在 Draft PR 提交。

本展示是靜態導覽，不直接呼叫該 API。上述是既有分支/Drive 紀錄，不是此展示分支重新做的網路 E2E。

阻塞與未完成項目

  • 原版 React 完整瀏覽器 E2E：BLOCKED_NOT_RUN。
  • 正式 Identity、RBAC、多租戶資料隔離、師傅資格：NOT_VERIFIED。
  • Production、正式案源、付款與金流：OWNER_GATE_CLOSED。

舊版存在示範錢包／帳密相關風險，不能直接作為公開 SaaS。
